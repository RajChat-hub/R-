# Native HTTP reverse proxy — development use

Build from repository root with CMake as in README. Run these in separate Linux terminals:

```sh
python3 unfaltering/examples/upstream.py
./unfaltering/build/unfaltering --check --config unfaltering/examples/proxy.ufc
./unfaltering/build/unfaltering serve --config unfaltering/examples/proxy.ufc
curl -i http://127.0.0.1:8080/
curl -i http://127.0.0.1:8080/app/hello
curl -i -X POST --data 'native proxy body' http://127.0.0.1:8080/app/echo
```

The Python app is only an independent demonstration upstream; the server and proxy remain native C++. The old valid server.ufc configuration remains supported.

```text
upstream local_app {
 address "127.0.0.1:9000";
 host "app.local";
 connect_ms 1000;
 write_ms 5000;
 response_ms 15000;
 forwarding replace;
}
route prefix "/app" { proxy local_app; }
```

Place these declarations inside the server block. Routes may contain exactly one root or proxy target. Exact routes precede longest segment-boundary prefixes. The complete original origin-form path and query are retained; /app is not stripped. Routes remain global across virtual hosts and are not authorization rules.

Upstream names are unique, at most 64 ASCII letters/digits/underscore/hyphen. Addresses must be explicit numeric IPv4:port; DNS, URLs, port zero, unspecified/multicast destinations and HTTPS are rejected. The optional Host is a validated fixed authority; by default it is the configured address and port. Unknown or duplicate fields and unresolved references fail before the listener starts.

connect_ms (default 2000), write_ms (default 5000), and response_ms (default 10000) accept 100–60000. They are absolute from transaction creation; response_ms includes connect/upload/response time and must be sized for the intended finite stream. There is no retry or pooling policy. Downstream write_ms is a no-progress timeout for proxy responses; request_ms bounds client request receipt.

forwarding is replace (default) or off. All incoming Forwarded, X-Forwarded-* and X-Real-IP are removed. replace generates X-Forwarded-For from the directly accepted peer, X-Forwarded-Proto=http, and X-Forwarded-Host from the validated request authority. No client-supplied proxy chain is trusted. Host comes from upstream configuration. Connection-nominated headers and standard hop-by-hop headers are stripped in both directions; framing headers are reconstructed.

buffer_bytes defaults to 65536, accepts 16384–262144 and must fit 2*header_bytes+1024. Each of the four wire queues is capped individually. memory_budget_bytes defaults to 67108864 (64 MiB), accepts 1 MiB–1 GiB and must admit at least one conservative connection reservation. Admission may therefore stop below max_connections. body_bytes retains its 1 MiB default, now accepts up to 64 MiB as a decoded streaming limit. response_body_bytes defaults to 1 GiB and accepts 0–1 GiB; it caps decoded response length without allocating that length.

Strict unsupported forms are rejected: Expect: 100-continue, chunk extensions, nonempty trailers, upgrade/101, CONNECT tunnels, duplicate Content-Length, CL+TE and transfer codings other than chunked. EOF-delimited upstream responses are supported, with downstream framing generated by the proxy. Configured upstreams and document roots must be trusted. Do not expose this development build as a production service.
